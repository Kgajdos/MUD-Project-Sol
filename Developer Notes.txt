DEVELOPER NOTES - 13 NOV 2025

Summary
-------
Today I performed a repository-wide sweep and fixed multiple runtime and design issues focused on the economy, ships, consoles, and initialization logic. I also added a YAML-backed skills registry with admin tooling and Evennia-focused tests for the economy flows.

Key changes
-----------
- Contracts / Corporations
  - Fixed Contract and ContractHandler signatures and status transitions.
  - Prevented storing live Evennia objects in persistent attributes: live contract objects are kept in ndb (runtime) and lightweight serializable summaries are stored in db to avoid pickling errors.
  - Leaders mapping normalized to employee -> title; promote/demote and notify flows updated accordingly.

- Ships / Ship spawning
  - Fixed ship cargo, capacity and save() logic; added proper checks when accepting freight contracts.
  - Ship spawn now creates and persists a stable shipID and stores the pilot as a serializable string (player.key) in `ship.db.pilot`; also stores a transient `ship.ndb._pilot_obj` for runtime messaging. This avoids requiring a server restart after spawning ships.

- Ship console / Menus
  - Restored and hardened the ship console command (`CmdShipConsole`) and EvMenu nodes. The `console` command now safely locates a nearby console object, guards against missing ship references, logs debug info, and presents friendly messages to the player.
  - `ShipConsole.ship_sheet` now populates and persists `ship.db.pilot` dynamically when the console is accessed by the ship owner so pilot shows up immediately.
  - Restored paginated destination list in `menunode_set_destination` and added Next/Previous navigation.

- Character initialization
  - Moved import-time random AttributeProperty initializations into `at_object_creation` for per-instance randomness (characters, enemies, etc.).

- Skills system
  - Added `typeclasses/skills.py` (YAML-backed registry) and `data/skills.yml` containing skill definitions.
  - Added a small admin command `@skills` to manage the registry at runtime (`commands/skill_admin.py`).

- Tests and CI
  - Added Evennia-style tests for corporations/jobs/freighter contract flows (`tests/test_economy.py`).
  - Ran the Evennia test harness; found and fixed a pickling error by moving live objects to ndb and storing serializable summaries in db.

- Misc
  - Updated `.gitignore` to exclude virtualenvs, keys, and IDE artifacts.
  - Various messaging and minor bug fixes (use of caller.msg vs self.msg, save() invocations, pagination, menu node resilience).

Why these decisions
-------------------
- Evennia DB attributes are pickled when stored; storing live typeclass objects caused runtime pickle errors. Storing only serializable summaries in `db` and keeping live objects in `ndb` is the safe pattern.
- Persisting `shipID` and storing `pilot` as a serializable key removes the need to restart the server to see the assigned pilot when spawning new ships.
- Moving randomness into `at_object_creation` guarantees unique per-instance values instead of a single import-time value.
